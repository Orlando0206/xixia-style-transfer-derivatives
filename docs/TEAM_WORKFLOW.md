# 团队协作流程

## 日常流程

1. 在 Issue 中确认任务范围和负责人。
2. 从最新 `main` 创建功能分支：`feat/功能名`。
3. 本地开发、自测并提交。
4. 推送分支后创建 Pull Request，关联对应 Issue。
5. 至少一位组员审阅通过后合并到 `main`。

## 推荐分工

- 产品与素材：需求、文化资料、素材版权记录
- 算法：风格迁移与图像处理
- 客户端：PyQt 页面、交互与状态管理
- 数据与测试：本地数据、测试用例、验收记录

## 仓库设置

维护者应在 GitHub 的 Settings → Branches 中为 `main` 启用分支保护：要求 Pull Request、至少 1 个审批、合并前分支保持最新。不要向 `main` 直接推送。

## 大文件与配置

- 模型、视频、设计源文件等大型资产使用 Git LFS 或团队云盘，并在 Issue/PR 中附链接。
- 密钥和本地配置使用未跟踪的 `.env` 文件；仓库只提交示例配置。
